## CORE ASSETS & STACK
- **Stack:** React Native, Expo, NativeWind, Zustand (or similar for state), Vercel (Target: Web). Do not hardcode legacy versions; use the latest stable releases compatible with each other.
- **Map:** Read `map.txt`. It is a 20x20 grid (S = Sea, L = Land, I = Island).
- **Rules:** Read `rules.txt`. Adhere strictly to piece hierarchy, movement rules, and setup phases.
- **Assets:** `images-blue/` and `images-yellow/` contain 20 unit types (`<unit>.png`) and `blank.png`. All are 512x512 squares with black frames and rounded corners.

## CRITICAL ARCHITECTURAL CONSTRAINTS
Before writing code, you must design the system around these non-negotiable requirements:

1. **Normalized State Management (Crucial for Performance):**
   A 20x20 grid means 400 cells. Do NOT store the full nested piece objects inside a 2D array. Use a normalized state (e.g., a dictionary of `piecesById` and a 2D array of `cellIds`). This prevents catastrophic re-renders when a single piece moves.
2. **Deep Stacking Logic:**
   An M7 ship can carry a Life Raft, which carries soldiers. Your piece data structure must support a tree-like `carriedPieces` array or nested IDs. 
3. **Fog of War & The "Blank" Asset:**
   The Game Engine must know the true identity of every piece, but the UI component must conditionally render `blank.png` for enemy pieces to hide their identity. If a cell contains a stack (like a loaded ship), superimpose a numerical badge on the UI to indicate the stack size.
4. **Viewport Interaction:**
   A 20x20 board will not fit on most screens. You must implement a scrollable viewport or a pan/zoom wrapper (e.g., using gesture handlers or CSS transforms for web) so navigating the board feels natural and high-end.
5. **Decoupled Game Engine:**
   Keep the game logic (combat resolution, valid moves, embarking/disembarking) completely separate from React components. Write them as pure TypeScript functions that update the global state.
